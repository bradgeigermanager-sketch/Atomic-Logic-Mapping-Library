To create a human-facing interface for your **Atomic Logical Artifact (ALA)** library, we will build a lightweight, self-contained web portal. Since you value non-nested structures, this interface uses a **"Tabbed-View" pattern** to show the 4 levels of detail (Simplified, Detailed, Logic, Evidence) without complex navigation.

### 1. The Interface Architecture

We will use a single HTML template that dynamically loads your ALA data.

#### **File: `template.html**`

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <title>DAMMS Knowledge Base</title>
    <style>
        .tab-content { display: none; padding: 20px; border: 1px solid #ccc; }
        .active { display: block; }
        nav button { padding: 10px; cursor: pointer; }
    </style>
</head>
<body>
    <h1 id="title"></h1>
    <nav>
        <button onclick="showTab('simplified')">Simplified</button>
        <button onclick="showTab('detailed')">Detailed</button>
        <button onclick="showTab('logic')">Derived Logic</button>
        <button onclick="showTab('evidence')">Evidence</button>
    </nav>

    <div id="simplified" class="tab-content active"></div>
    <div id="detailed" class="tab-content"></div>
    <div id="logic" class="tab-content"><pre id="logic-code"></pre></div>
    <div id="evidence" class="tab-content"></div>

    <script>
        function showTab(id) {
            document.querySelectorAll('.tab-content').forEach(t => t.classList.remove('active'));
            document.getElementById(id).classList.add('active');
        }
    </script>
</body>
</html>

```

### 2. The Logic to Generate the Interface

Instead of hand-coding every page, you should have a script that **transforms your ALA Markdown files into static HTML pages** whenever you run your indexer.

#### **Python Extension: `generator.py**`

This script takes your Markdown ALAs and injects them into the `template.html` to create a browseable wiki.

```python
import frontmatter
import markdown

def generate_html(ala_path, template_path="template.html"):
    post = frontmatter.load(ala_path)
    # Convert MD parts to HTML fragments
    content = markdown.markdown(post.content)
    
    with open(template_path, 'r') as f:
        html = f.read()
    
    # Simple injection (can be expanded to use templates like Jinja2)
    final_html = html.replace('<h1 id="title"></h1>', f'<h1>{post.metadata["title"]}</h1>')
    final_html = final_html.replace('<div id="simplified" class="tab-content active"></div>', 
                                     f'<div id="simplified" class="tab-content active">{content}</div>')
    
    with open(f"docs/{post.metadata['uid']}.html", 'w') as f:
        f.write(final_html)

```

### 3. Proposed Library Directory Structure

This keeps your raw data, your logic, and your human-viewable documentation organized:

```text
/my_knowledge_base/
├── library/            # Your source ALAs (Markdown files)
├── indexer.py          # The script to build Index.json
├── generator.py        # The script to build the Wiki HTML
├── docs/               # The generated Wiki site (Web Interface)
└── data/               # Raw evidence (Logs, CSVs)

```

### **Procedure: The "Publishing" Loop**

1. **Draft:** Create/Edit `library/ALA-001.md`.
2. **Index:** Run `indexer.py` (Updates `Index.json` for machines).
3. **Build:** Run `generator.py` (Creates/Updates `docs/ALA-001.html` for people).
4. **Deploy:** View the `/docs/` folder in any browser to browse your encyclopedia.
